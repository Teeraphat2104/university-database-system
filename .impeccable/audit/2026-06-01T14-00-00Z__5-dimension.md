# 5-Dimension Technical Audit

**Project:** University Database System  
**Date:** 2026-06-01  
**Design North Star:** "The Quiet Archive" (Terracotta `#E66239`, flat surfaces, 1px borders, single accent)  
**Base Score:** 23/40 (from critique)  

---

## 1. Accessibility (WCAG AA)

### P0 — div-as-button in DashboardRecent
- **File:** `src/app/(app)/dashboard/dashboard-recent.tsx:25-48`
- **Issue:** Row `<div>` has `onClick` but no `role="button"`, `tabindex`, or keyboard handler. Screen readers won't announce it as interactive; keyboard-only users can't activate it.
- **Fix:** Use `<button>` styled as row, or add `role="button" tabIndex={0} onKeyDown={...}` with Enter/Space handling.

### P0 — No skip-to-content link
- **Issue:** All page layouts lack a skip-to-content anchor. First focusable element on every page loads the full nav tree.
- **Fix:** Add `#skip-to-main` link at top of `<body>` in root layout (`src/app/layout.tsx`).

### P0 — No focus-visible rings on interactive elements
- **Issue:** Many custom components rely on `focus:ring-2` but this shows on mouse click too (annoying for mouse users) and some elements have no focus indicator at all (e.g., `DashboardRecent` row div, `theme-toggle.tsx` button, `tree-nav.tsx` branch toggles).
- **Fix:** Use `focus-visible:` for keyboard-only focus rings, ensure every interactive element has a visible focus indicator.

### P1 — ThemeToggle lacks aria-label
- **File:** `src/components/theme-toggle.tsx:11`
- **Issue:** Icon-only button `<button type="button" onClick={toggleTheme}>` has no `aria-label="Toggle theme"` or `aria-label="Switch to dark mode"`.
- **Detection:** The critique's P0 already flagged this.

### P1 — Modal close button lacks aria-label
- **File:** `src/components/modal.tsx` (read earlier)
- **Issue:** The X close button is icon-only with no `aria-label`.

### P1 — Forgot password button dead (no onClick)
- **File:** `src/app/(auth)/login/login-form.tsx` (read earlier)
- **Issue:** "Forgot password?" is a `<button>` with no `onClick` handler. Dead element on the page — confusing for screen readers.

### P2 — Typewriter effect has no aria-live region
- **Files:** `src/app/landing-search.tsx`, `src/components/landing/hero-section.tsx`
- **Issue:** The cycling placeholder text updates dynamically but has `aria-live="polite"` — screen readers won't announce changes.
- **Fix:** Add `aria-live="polite"` to the containing element.

### P2 — prefers-reduced-motion not respected
- **Files:** All components with framer-motion animations (hero, stats, browse grid, category showcase, recent PDFs, theme toggle, select dropdown)
- **Issue:** Zero animations check `window.matchMedia("(prefers-reduced-motion: reduce)")`. Users with vestibular disorders get full motion.
- **Fix:** Use Framer Motion's `useReducedMotion()` or a global CSS `@media (prefers-reduced-motion: reduce) { * { animation: none !important; } }`.

### P3 — Tree nav branch chevrons lack aria-expanded
- **File:** `src/components/tree-nav.tsx`
- **Issue:** Collapsible branches don't communicate their expanded state to AT.

### P3 — Dashboard stats section has no heading hierarchy
- **File:** `src/app/(app)/dashboard/page.tsx`
- **Issue:** Stat cards use `<p>` for labels; no `<h2>/<h3>` landmarks for screen reader navigation through the dashboard regions.

## 2. Performance

### P2 — All entrances use framer-motion without layout shift consideration
- **Issue:** 5+ components use `motion.div` with `initial={{ opacity: 0, y: 20 }}` → `animate="visible"`. These are content components (not decorative), so they push content down on mount — causing cumulative layout shift (CLS). The viewport-lazy loading (`whileInView`) means cards pop in as user scrolls, each triggering a layout reflow.
- **Fix:** Reserve space with explicit `min-h` or `min-height` containers, or animate only opacity (not layout-affecting transforms like `translateY`).

### P2 — CategoryImage loads all images via POST fetch at mount
- **File:** `src/components/category-image.tsx`
- **Issue:** Every `CategoryImage` instance fires `POST /api/category/{id}/image` on mount. On a page with 10+ category cards, this is 10+ sequential requests. No request deduplication beyond the in-memory cache (which only helps within a session, not on first load).
- **Fix:** Batch-load category images, pre-populate SSR with data from the server, or use Next.js Image optimization.

### P2 — Watch mode re-renders on every keydown
- **File:** `src/app/landing-search.tsx` (typewriter effect)
- **Issue:** The search landing typewriter cycles through placeholders on interval. Even when the search field is empty, the component re-renders on every typewriter tick, causing unnecessary React re-renders of the entire search section.
- **Fix:** Memoize the typewriter effect or replace with CSS-only placeholder cycling.

### P3 — No image optimization for category images
- **File:** `src/components/category-image.tsx:59`
- **Issue:** Uses raw `<img>` tag instead of Next.js `<Image>`. No lazy loading, no responsive sizing, no WebP conversion.
- **Fix:** Use `next/image` with `loading="lazy"`.

## 3. Theming (Light/Dark)

### P1 — `brightness(1.1)` on dark mode produces washed-out hover
- **Issue:** Primary buttons use `hover:brightness-110` which brightens the already-warm Terracotta. On dark mode (`#0a0a0a` background), a brighter Terracotta reads as washed-out pink, not an intentional hover state.
- **Fix:** Use `filter: brightness(1.1)` only in light mode; in dark mode use `filter: brightness(1.2)` or a color shift approach.

### P2 — Dark mode not tested on browse categories page sidebar
- **File:** `src/app/browse/categories/page.tsx`
- **Issue:** The public browse pages don't use the app shell, so they have a standalone top bar with `backdrop-blur-xl bg-background/60`. The `bg-background/60` with backdrop-blur works differently in dark mode — on `#0a0a0a` background, the semi-transparent top bar may not provide sufficient contrast.
- **Fix:** Verify and adjust.

### P2 — Modal in dark mode has no border contrast
- **File:** `src/components/modal.tsx`
- **Issue:** The native `<dialog>` element gets its border from `border-border` which is `#262626` in dark mode — on `#0a0a0a` background, the dialog surface is `#0a0a0a` (same as page), so the 1px border is the only visual separation. The border at `#262626` on `#0a0a0a` is roughly a 2.5:1 contrast ratio — hard to perceive.
- **Fix:** Give the dialog a slightly lighter dark-mode background (`#141414` or `#1a1a1a`) so the border is visible.

## 4. Responsive

### P2 — Sidebar overlay missing focus trap
- **File:** `src/components/app-shell.tsx` (mobile sidebar overlay)
- **Issue:** On mobile (<768px), the sidebar opens as an overlay. When open, focus can still tab outside the sidebar — users can Tab behind the overlay. No focus trap.
- **Fix:** Implement focus trapping within the mobile sidebar when open.

### P2 — Touch targets below 44px on mobile cards
- **Files:** `src/app/(app)/dashboard/dashboard-recent.tsx`, `src/components/landing/category-showcase.tsx`
- **Issue:** WCAG 2.5.8 requires 44x44px touch targets. Category cards use a Link wrapping content, but the click target is only as large as the text content. Dashboard recent rows have `IconEye` (16px) as the only apparent click indicator.
- **Fix:** Ensure all interactive targets meet 44x44 minimum on mobile.

### P2 — Browse grid collapses abruptly at sm breakpoint
- **File:** `src/components/browse/browse-pdf-grid.tsx:45`
- **Issue:** Grid goes from `sm:grid-cols-2` → `grid-cols-1` at 640px. The 1-column layout on phones is fine, but padding/margins don't adjust — cards run edge-to-edge on small screens.
- **Fix:** Add `px-4` at the container level so cards have breathing room on mobile.

## 5. Anti-Patterns & Design System Drift

### P0 — Stats section violates DESIGN.md Don't list
- **File:** `src/components/landing/stats-section.tsx`
- **Issue:** The landing stats section uses 4 different colors (orange `#E66239`, blue `#3B82F6`, purple `#8B5CF6`, teal `#14B8A6`) for stat cards. This is an explicit violation of DESIGN.md: "Don't use rainbow-colored stat cards with per-item gradients" and "The Restraint Rule: Terracotta occupies no more than 10% of any given screen."
- **Fix:** All 4 stats cards use neutral palette with Terracotta icon only.

### P0 — Animated gradient hero contradicts "Quiet Archive"
- **File:** `src/components/landing/hero-section.tsx`, `src/components/landing/animated-gradient.tsx`
- **Issue:** The hero section features animated gradient blobs (4 `blur-3xl` divs cycling through positions), a typewriter effect, and a scroll-down indicator. This is the opposite of "quiet" — it's visually loud, motion-heavy, and emotionally reminiscent of 2022-era AI-generated landing pages.
- **Fix:** Replace with a static hero: a clean headline, a quiet subtitle, and the search bar. No gradient blobs, no typewriter, no scroll indicator.

### P1 — Browse categories page uses `bg-gradient-to-b from-primary/5`
- **File:** `src/app/browse/categories/page.tsx:28`
- **Issue:** The section background uses `bg-gradient-to-b from-primary/5 via-primary/[0.02] to-background`. This is a gradient surface, which violates the "Flat By Default" rule. The Quiet Archive doesn't do gradient backgrounds.
- **Fix:** Use solid `bg-muted` or no background at all.

### P1 — Framer Motion on content cards causes layout shift (see Performance)
- **Files:** `recent-pdfs.tsx`, `browse-pdf-grid.tsx`, `category-showcase.tsx`, `stats-section.tsx` (individually, but in aggregate)
- **Issue:** Content-card animation (stagger, y-offset, opacity) is a UX anti-pattern for content discovery. Users scan a grid; animated entrances create a "slot machine" effect where content appears asynchronously. This fights the user's ability to scan and compare.

### P2 — `backdrop-blur-xl` on top bars
- **Files:** `src/app/browse/categories/page.tsx:13`, `src/app/browse/pdfs/[id]/page.tsx:29`
- **Issue:** `backdrop-blur-xl bg-background/60` on the sticky top bar. The "Quiet Archive" doesn't do frosted glass. This is glassmorphism-adjacent.
- **Fix:** Use solid `bg-background` with `border-b border-border`.

### P2 — Icon-only button without aria-label (cataloged under a11y but anti-pattern too)
- **File:** `src/components/theme-toggle.tsx`
- **Issue:** This pattern recurs (modal close, theme toggle). Icon-only buttons without labels are a systemic gap.

### P3 — `as const` type assertion on easing arrays repeated 8+ times
- **Files:** Many components
- **Issue:** `ease: [0.25, 0.4, 0.25, 1] as const` is repeated across every Framer Motion variant. This is noise. Extract to a shared constant (already defined in DESIGN.md motion tokens).

## Summary by Dimension

| Dimension | Severity Score | Key Issues |
|-----------|---------------|------------|
| Accessibility | **P0** | div-as-button, skip-to-content, focus rings missing |
| Performance | **P2** | CLS from animated entrances, N+1 image requests |
| Theming | **P1** | brighten filter in dark mode, modal contrast |
| Responsive | **P2** | No focus trap on mobile sidebar, touch targets |
| Anti-Patterns | **P0** | Rainbow stat cards, animated gradient hero (contradict north star) |

**Depth Assessment:** The codebase has a solid foundation (clean component separation, Prisma, proper loading states) but the surface layer drifts significantly from the DESIGN.md north star. The biggest gaps are (1) the animated gradient landing page, (2) rainbow stat cards, and (3) systematic accessibility gaps. All three are fixable within the existing component architecture.
